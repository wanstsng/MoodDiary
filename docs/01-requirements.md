# Анализ технического задания

Документ фиксирует, как требования ТЗ по МДК 01.03 закрываются в проекте
«Дневник», и служит чек-листом при сдаче работы.

## 1. Выбранная тема

**Тема №16 «Дневник»** — личные заметки с настроением.
Рекомендованная ТЗ изюминка: поиск по тексту, экспорт в PDF.

Предметная область: пользователь ежедневно фиксирует события и своё состояние.
Каждая запись принадлежит одной категории (Личное, Работа, Здоровье…) и может
быть помечена произвольным числом тегов (отпуск, спорт, семья…).

## 2. Обязательные требования и как они закрываются

### 2.1. Экраны (минимум 5)

| № | Экран ТЗ | Экран приложения | Что реализовано | Неделя |
|---|----------|------------------|-----------------|--------|
| 1 | Список | `EntryListFragment` | Список записей, строка поиска, FAB добавления | 5 |
| 2 | Добавление/Редактирование | `EntryEditorFragment` | Форма, валидация, «Сохранить»/«Отмена» | 6 |
| 3 | Детальный просмотр | `EntryDetailFragment` | Все поля записи, «Редактировать»/«Удалить» | 7 |
| 4 | Статистика | `StatsFragment` | Столбчатая и круговая диаграммы + показатели | 9 |
| 5 | Настройки | `SettingsFragment` | Тема, сортировка, формат даты, экспорт | 10 |

Навигация: `BottomNavigationView` (Дневник / Статистика / Настройки) плюс
Navigation Component для переходов список → деталь → редактор.

### 2.2. База данных (минимум 3 основные таблицы + 1 промежуточная)

| Требование ТЗ | Реализация |
|---------------|------------|
| 3 основные таблицы | `categories`, `entries`, `tags` |
| Связь «один-ко-многим» | Одна категория → много записей (`entries.category_id`) |
| Связь «многие-ко-многим» | Записи ↔ Теги через `entry_tags` (4-я таблица) |
| Внешние ключи | Все связи объявлены через `FOREIGN KEY` с `ON DELETE CASCADE` |

Дополнительно создаётся виртуальная таблица `entries_fts` для полнотекстового
поиска — она обслуживает изюминку и не заменяет основные таблицы.

Подробная схема — в [03-database-design.md](03-database-design.md).

### 2.3. Работа с данными

| Функция ТЗ | Реализация | Неделя |
|-----------|------------|--------|
| CRUD | Создание, чтение, обновление и удаление записей | 3, 5–7 |
| Поиск | Полнотекстовый поиск по заголовку и содержимому (FTS4) | 8, 11 |
| Фильтрация | Три фильтра: по настроению, по категории, по периоду дат | 8 |
| Сортировка | По дате (новые/старые) и по заголовку | 8 |
| Статистика | Экран с графиками на реальных данных пользователя | 9 |
| Пустые состояния | Заглушка с предложением создать первую запись | 5 |

### 2.4. Обработка ошибок и состояния загрузки

| Ситуация | Реализация |
|----------|------------|
| Пустые поля формы | Подсветка `TextInputLayout` красным + текст ошибки + `Snackbar` |
| Удаление записи | `MaterialAlertDialog` «Удалить запись?» с подтверждением |
| Долгие операции | `CircularProgressIndicator` при загрузке и при экспорте в PDF |
| Ошибка сохранения | Ошибка перехватывается в репозитории, показывается `Snackbar` без краша |
| Офлайн-режим | Приложение полностью офлайн — данные хранятся локально в SQLite |

### 2.5. Качество кода

| Критерий ТЗ | Реализация |
|-------------|------------|
| Архитектура | MVVM: `Fragment` → `ViewModel` → `Repository` → `DAO` |
| Названия | Все классы, методы и переменные — на английском языке |
| Структура пакетов | `data.model`, `data.database`, `data.repository`, `ui`, `ui.adapters`, `viewmodels`, `utils` |
| Комментарии | KDoc у всех публичных классов и методов, пояснения к сложным запросам |
| Работа с БД в фоне | Все запросы — `suspend`-функции и `Flow`, выполняются на `Dispatchers.IO` |

## 3. Изюминка

1. **Полнотекстовый поиск (FTS4).** Таблица `entries_fts` синхронизируется с
   `entries` триггерами. Поиск работает по словоформам и подсвечивает найденные
   фрагменты прямо в списке записей.
2. **Экспорт в PDF.** Кнопка «Экспорт в PDF» в настройках формирует
   многостраничный документ со всеми записями (дата, настроение, категория,
   теги, текст) через `PdfDocument` и открывает системный диалог «Поделиться».

Обе функции органично встроены в логику дневника: поиск нужен, когда записей
много, а PDF — способ сохранить дневник за пределами телефона.
